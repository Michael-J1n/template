## 做题注意

1. nq 问题中，有些要取不固定 mod 数，不要叫 p！线段树板子中 p 是代表 pos 的变量，不要把他变成全局变量

2. **离线** 区间询问，记得想莫队是否能维护。关键在于能否均摊快速的将元素贡献加入或删除窗口

## 树形数据结构 VS 线性数据结构

一个问题是，对于 nq 问题，该使用线段树维护还是分块维护。除去使用数据规模来看 sqrtn 是否能过之外，还有几个原则：

1. 区间答案/修改可以按照左右两块分别贡献并合并，优先考虑线段树

2. 如果**查询依赖块内的有序性**，例如查询区间 < k 个数 / 第 k 小的数，区间值域计数，通常使用分块，对于每块再**维护一个排序数组**

3. 对整块可以用**势能特殊优化**的操作：**区间开平方 / 区间取mod：使用分块**，在懒标记已经到势能最小值就可以不去操作（或直接维护一个 done[b]）

4. 一些奇怪的操作，也优先考虑分块：**区间众数（蒲公英trick），区间出现次数 / 颜色种类数（如果可以离线，要考虑莫队）**，**区间频率统计（维护频率表）**，区间相同数对数量

## 并查集相关

1. 对于扩展域并查集，除了经典的捕食/敌友的关系，还有一些隐藏**二元状态**也可以被扩展域并查集表示：【P14799】给无向边图，一个合法路径 {v1,v2,...,vn} 是满足 v1=s，对于奇数 vi < vi+1，否则 vi > vi+1 的路径（路径编号小大交错）。求对于每个点作为 s 时，有多少点是无论如何不可达的。
定义 up[u] 为从 u 出发下一步要走编号更大的点，down[u] 为从 u 出发下一步要走编号更小的点进行拆点，是二元状态可以在扩展域并查集中表示：up[u]=u, down[u]=u+n
那么对于一个边 i-j (i < j)，up[i] 和 down[j] 就可以连边。
对于每个点，他所在连通块里的所有点就是它出发可以到达的点（链式激活）。那么他作为 s 时，可达的点个数就是此连通块中真实编号点的出现次数，可以这样统计：
```CPP
for (int i = 0; i < n; ++i) {
    int x = s.find(i), y = s.find(i + n);
    // x: up[i] 所在连通块根节点；y: down[i] 所在连通块根节点
    ++cnt[x];
    if (x != y) ++cnt[y];
}
```

2. 给定字符串 S 与 T，S 中给定一些位置可以交换，问 S 能否变 T：把交换的都搞到一个连通块，判断每个连通块 S 的字符频率集合和 T 在这个块中的字符频率集合是否相等

3. 奶酪问题（P3958）判断下表面能否到上表面/河东岸能否到河西岸：建立并查集，最后看两端点所属节点是否联通。一般的做法就是读入先看每个形状和两边是否相交，如果是就连接。然后做一个 O(n^2) 暴力检查，如果**相交** 就两两 unite。并查集 0 和 n+1 代表两端，中间节点是图形编号

4. 并查集可以很好的处理**成环**的情况：给定一个图，要求所有编号 <=k 的点都不在任何一个简单环上，求最少删多少边。首先对于编号 >k 的点无所谓，所以不应该删，先把所有两端 >k 的边连接起来。对于每个剩下的边，用**并查集尝试联通。如果在一个连通块，说明这条边加进来会让端点进入环**，不能加。否则可以在连通块连边。

5. **带权并查集**经典应用：给定 n 个 stack，每个上面放着一个方块，编号 0 到 n-1。
维护两种操作：M u v 与 C u，第一个代表把含有编号 u 的 stack 整体放到含有编号 v 的 stack 上方，第二个代表查询编号为 u 的方块下面有多少个方块。考虑维护一个大小为 n 的带权并查集，节点到根节点的距离代表这个节点下面的方块的数量。

对于第一个操作，假设 u 的根为 pu，v 的根为 pv。对于 pu 块中所有点，它的下方都会多出 sz[pv] 个方块，因此把 pu 到 pv 连边，边权为 sz[pv]。这样原本在 pv 块的方块值不变，在 pu 块的所有方块到根节点的距离都增加了 sz[pv].
对于第二个操作，直接输出 x 到 px 的距离即可。

6. 有时候扫描每个 i，把他的值贡献到 s.find(i) 上是一个有用的统计技巧

7. 给定一些区间和信息，询问一些区间和能否确定：转化为 pre[r] - pre[l-1] = s，用**带权并查集**从 l-1 到 r 连 s 的边，查询时看 l-1 与 r 是否在一个连通块即可

8. **【重要！】** **并查集给一个连通块共同加上一个值**的处理：给定一个图，两个操作：1 a b 与 2 p t，第一个代表连接 a，b 所在的连通块，第二个代表 p 所在的连通块每个点加 t。最后查询每个点的值（初始都为 0）

使用**带权并查集与虚拟根节点**：注意到想给连通块加上一个值，把当前根连接到虚拟根，这条边边权设置为 t，那么路径压缩时每个点到根的距离都会 +t。

9. **【重要！】** **在数组上维护关键点的并查集**
【P8010】省去推式子环节，需要维护两个操作：1. 对于前缀 [0,id] 共同加 x；2. 询问前缀 [0,r] 中最大值出现的最后一个下标。
首先不考虑操作 1，那么定义满足 a[i]>=max(a[0],..,a[i-1]) 的值为关键值，下标 i 为关键下标，关键值是一个不减的序列；对于点 i，它的查询结果即为左边第一个关键下标。

对于前缀加操作，感性的考虑，由于前缀关键值都增长相同，不会变化。后面的关键值有些会变小从而被取消，那么他所管辖的那一块元素的答案会变成前一个关键下标。这样对于整个一块元素的答案迁移可以使用并查集，只需要操作根即可。不变量为：find(i) 代表 i 左侧最近一个关键下标。

具体来说，初始化 pa[i] 为 i 左侧最近的关键下标。再维护两个量：nxt[u] 代表关键下标 u 右边的第一个关键下标，delta[u] 代表 a[nxt[u]] - a[u]（注意到关键值之间只有相邻差有用而不需要真实值，对于相隔比较多的关键值可以用 delta 的累加（类似前缀和差分）来处理）；注意额外添加一个 delta 值为 LINF 的哨兵下标 n 作为最后一个关键下标的 nxt 值：
```CPP
struct UFS {
	int n;
	vi pa, nxt;
	vll delta;  // a[nxt] - a[cur]
	UFS(vector<ll>& a) : n(a.size()) {
		pa.resize(n), nxt.assign(n, n), delta.assign(n, LINF);
		for (int i = 0; i < n; ++i) pa[i] = i;
		int last = 0;
		for (int i = 1; i < n; ++i) {
			if (a[i] >= a[last]) {
				nxt[last] = i;
				delta[last] = a[i] - a[last];
				last = i;
			} else {
				pa[i] = last;
			}
		}
	}
}
```
对于常规的找归属关键下标的 find 函数，使用路径压缩即可：
```CPP
int find(int x) {
    if (x != pa[x]) pa[x] = find(pa[x]);
    return pa[x];
}
```
关键在于处理前缀加的事件：
假设对于前缀 [0,id] 加上 x，那么先找到 u = find(id) 为其关键下标，然后对于考虑关键下标什么时候能把之后的关键下标给“消除”：假设对于 v = nxt[u]，那么现在 u 变成 u+x，两者差就会变为 a[v]-a[u]-x = delta[u]-x；如果 delta[u]-x < 0 了，说明形成逆序对可以把 v 删除。删除 v 时，把 nxt 指针相连之外，还要维护 v 的 pa 值连到 u 把所属块给 merge 进来，并且还需要更新 delta[u] += delta[v]（差分到前缀和思想）。然后重复这个过程直到关键值可以不减：
```CPP
void add(int x, ll y) {
    int u = find(x);
    while (u != n && delta[u] - y < 0) {
        int v = nxt[u];
        delta[u] += delta[v];
        nxt[u] = nxt[v];
        pa[v] = u;
    }
    delta[u] -= y;
}
```
查询 id 时返回 find(id) 即可。

## 树状数组/线段树相关

1. 给定一个长度为 n 初始全为 L 的字符串，每次询问给出一个 pos，将 pos 处的 L 变成 R，或 R 变成 L。求最大交替串长度
这个模型优先联想到“差分”的模型：考虑 d[i] = a[i+1]!=a[i]，那么最大交替串长度就是 d 上的最长 1 序列再加 1. 对 d 建立线段树，只有单点set操作。节点类似小白逛公园trick一样维护 pre,suf,mx

2. 给 n 个长度的序列，每次操作1为给 l,r 上所有数添加一种全新种类，操作2为询问 l,r 上不同种类数。
考虑历史区间 [l,r] 如果在 [ql,qr] 内，那么必有 l<=qr && r>=ql，因此答案为 cnt(l: l<=qr) - cnt(r: r <=ql-1)，用两个 bit 维护前缀和即可
这个答案统计一定是不重不漏的，因为 r<=ql-1 一定有 l<=qr，把不符合的子集减去了。

3. **【重要】** **坐标轴反演trick**
【P10673】，每次分糖给 k 个学生，愤怒值为每个学生拿到重复的糖数量减一的和，每次操作加入一个种类的一颗糖，删除一个种类的一颗糖，以及给定 k 查询愤怒值
分析：对于 x 的频率 cnt[x]>k，对于愤怒值贡献 cnt[x]-k，因此答案为 sum_x max(0, cn[x]-k)
sum_x max(0, cnt[x]-k) = sum_{cnt[x]>=k} cnt[x]-k；如果横轴 x 纵轴 cnt[x]，不好处理 cnt[x]>=k 的条件

这种**有关频率的题目，横看成岭侧成峰，从 x->cnt[x] 的视角换成 f->num[f] 的视角**，即从每个数->频率改成：频率->拥有这个频率的数的个数
用**换轴 trick**，改为记录频率桶 f 和 num[f]：横轴频率，纵轴频率对应的糖果数

一个 >=k 的频率 f 会贡献 f-k，这个频率共有 num[f] 个值，总贡献 num[f]*(f-k)
sum_x max(0, cnt[x]-k) = sum_{f>=k} num[f] * (f-k) = sum_{f>=k} f*num[f] - k * sum_{f>=k} num[f]

因此可以开两颗 BIT，一个记录 f->num[f]，一个记录 f->f*num[f]；注意频率最高会有 n+Q，bit 的大小要开 n+Q


## 分块相关

1. **交换元素的动态逆序对问题**：给定一个数列，每次询问交换两个数的值再输出当前逆序对个数。考虑交换 (u,v) 的值，原先 a[u]=x, a[v]=y。关键观察是：对于下标 [0,u-1] 以及 [v+1,n] 的元素对于逆序对个数的贡献不会发生变化。因此只需要考虑下标 (u,v) 间的元素对于答案的贡献增量。

令 lo = min(x,y), hi = max(x,y), sgn = x < y ? 1 : -1；对于中间元素 z，如果 z = lo 或 hi，对答案增量为 sgn；如果 lo < z < hi，对答案增量为 2 * sgn。这是一个区间 rebuld sorted vec + 值域统计问题，直接使用分块解决。复杂度 O(n log n + q sqrt n)

2. **暴力 + 暴力 = 分块** 当有个东西要维护，思考暴力的时候 要么查询 O(1) 修改 O(n)，要么修改 O(n) 查询 O(1)，那么就可以想到分块了。直接分为 sqrt n 个块，平衡两种暴力，达到查询 O(sqrt n) 与修改 O(sqrt n)。

例如：【P3203弹飞绵羊】给定 n 个数 k[i]，当绵羊到点 i 时会被弹到 i + k[i]，单点修改 k，查询对于 i 要弹几步可以弹飞。试想没有修改，那么直接倒序预处理 res[i] = res[min(n,i+k[i])]+1 即可，其中哨兵 res[n]=0。这样查询就是 O(1) 的，有一个 O(n) 的预处理。
但是当加入修改后发现当前的 k[i] 改变最坏会影响 O(n) 个前继点，更新复杂度过大。
另一方面，如果不做预处理，每次修改就改 k，查询就沿着链一直跳，这样修改是 O(1) 的，查询是 O(n) 的。如何平衡这两种暴力的复杂度呢？分块！

首先还是像第一种做法那样预处理；对更新，更新点所在块内的前继点都做一次第一种暴力的连带更新。查询的时候按照第二种方法沿着链走更新。
假设划分为 sqrt n 块，每个点维护：to[i] = i 跳出当前这块第一次的落点，cnt[i] = i 跳到 to[i] 的步数
那么修改只需要修改本块所有点的 to 和 cnt，这是因为别的块的 to 和 cnt 不会因为当前块变化影响。
对于查询，沿着 i->to[i] 的链跳即可，最多 sqrt n 次跳跃。至此，达到了 sqrt n 的修改和查询的平衡：
```CPP
struct blockDecomposition {
    int n, B, m;
    vector<int> k;
    vector<int> to, cnt;  // to[i] = i 弹到第一个不在同块的位置；cnt[i] = i 弹到 to[i] 的次数
    blockDecomposition(const vi& _k) : n(_k.size()) {
    	k = _k;
        B = sqrt(n) + 1;
        m = (n + B - 1) / B;
    	to.resize(n), cnt.resize(n);
    	for (int i = n - 1; ~i; --i) update(i);
    }
    void update(int p) {
    	int nxt = min(n, p + k[p]);
    	if (nxt == n) to[p] = n, cnt[p] = 1;
    	else {
    		if (p / B != nxt / B) to[p] = nxt, cnt[p] = 1;
    		else to[p] = to[nxt], cnt[p] = cnt[nxt] + 1;
    	}
    }
    void modify(int p, int v) {
    	k[p] = v;
    	int l = p / B * B;
    	for (int i = p; i >= l; --i) update(i);
    }
    int query(int p) {
    	int res = 0;
    	while (p != n) res += cnt[p], p = to[p];
    	return res;
    }
};
```
当然，这个可以用 LCT 动态树的 link 和 cut 操作直接秒杀，并有期望更优复杂度。但是这种平衡查询和修改从而启发进行的分块做法是很值得记住的。


## 根号分治相关

对于一些题目，一次关于 x 的查询复杂度为 O(n/x)，或是：有两种实现，一种修改 O(n) 查询 O(1) 另一种修改 O(1) 查询 O(n)，那么就要联想到使用**根号分治**
例如，洛谷弹飞绵羊的分治做法，就是平衡了修改和查询的O(n)与O(1)到 O(sqrtn)；
另外，考虑一些常见可以分治的结构：
    - 一个图中度数较大的点：图一共有 2m 度数，那么度数 >B 的顶点只有 O(m/B) 个。对于轻点，邻居少，暴力查；对于重点，总数少，维护数据结构
    - 一个序列中出现次数较多的值：所有值的出现次数之和是 n，那么出现次数 > B 的值只有 O(n/B) 个。对于低频值，直接枚举它的所有出现位置；对于高频值，总数少，可以预处理或单独维护答案
    - 带步长 k 的操作：当 k > B 时，一次操作最多访问 O(n/B) 个位置，可以直接暴力；当 k <= B 时，可能访问很多位置，但小步长只有 B 种，可以对每个小 k 预处理
    - 集合大小：如果所有集合大小之和是 S，那么大小 > B 的集合只有 O(S/B) 个。对于小集合直接枚举元素；对于大集合，总数少，可以预处理它和其他集合的交集、贡献等信息
    - 区间长度：对于长度 <= B 的短区间，可以直接暴力处理；对于长度 > B 的长区间，如果这些区间互不相交或总长度受到限制，那么长区间数量很少，可以单独处理
    - 因数对：对于 xy <= n，不可能同时有 x > sqrt(n) 且 y > sqrt(n)。因此可以按 sqrt(n) 把因子分成小因子和大因子；小因子直接枚举，大因子对应的小因子很少，可以通过 n / x 得到
    - 出现位置间隔：如果一个值出现很多次，就属于重值，总数少，可以预处理相邻位置、距离或查询答案；如果出现很少，就是轻值，直接枚举所有出现位置即可
本质上都可以记成一句话：某个量的总和有限，所以“大对象”数量少；小对象单次暴力，大对象预处理或维护。

1. 【2107D】给定数组与两种类型操作，操作 1,p,v 将 a[p] 加上 v，操作 2,x,y 要求 a[y]+a[y+x]+a[y+2x]+...
发现这是带步长（即为x）的操作；对于大 x，不妨设 x>=B，询问访问的位置只有 n/B 个，因此可以暴力求解；
对于 x < B，询问2访问的位置很多，但是这样的 x 只有 B 种，对于小于 B 的所有 x 维护 sum[x][y]=a[y]+a[y+x]+a[y+2x]...，那么询问2可以O(1) 得到。
对于第一种操作，除去 a[p]+=v 以外，对于所有小于 B 的 x，他出现在 sum[x][y] 中 <=> y+kx=p，即只需要在 sum[x][p%x] 上加上这个值即可


## 离线处理/莫队相关

1. 对于莫队，频率桶是非常常用的维护结构，有些情况这两个会一起出现：cnt[x] = 值 x 的频率，ccnt[f] = 频率 f 对应的值个数；这有助于 O(1) 均摊的 add/del
例如：动态的求 frq 众数（即最大频率）（或判断以及求绝对众数）；关键观察在于删除一个 x 的出现最多会让 mx 回退 1：
```CPP
vector<int> cnt(tot);                   // cnt[x] = 值 x 对应的频率
vector<int> ccnt(n + 1);				// ccnt[f] = 频率 f 对应的值个数
auto add = [&](int i) -> void {         // 下标为 i 的元素进入查询区间
    int x = a[i];
    --ccnt[cnt[x]];
    ++cnt[x];
    ++ccnt[cnt[x]];
    mx = max(mx, cnt[x]);
};
auto del = [&](int i) -> void {         // 下标为 i 的元素离开查询区间
    int x = a[i];
    --ccnt[cnt[x]];
    --cnt[x];
    ++ccnt[cnt[x]];
    if (!ccnt[mx]) --mx;
};
```

2. 对于频率桶，还有个非常重要的根号性质：**任意区间（包括整个数组）的不同频率数只有 sqrt n 种**：这是因为频率从 1 开始，假设到 k，那么 1+2+..+k=O(k^2) < O(n)，因此不同频率数的量级是 sqrt n 的。
这个性质有时候会结合莫队的**复杂度平衡**问题：
由于莫队复杂度 n sqrt n T + q A，其中 T 为增删复杂度，A 为回答复杂度。有时候增删很慢但回答 O(1)，要想是否可以做某种变化到增删很快但回答较慢（例如 sqrt n）；这样复杂度就是 n sqrt n + q sqrt n，可以过。
例如：询问离线，每次问区间内 f * ccnt[f] 的最大值。首先莫队 + 线段树每次对于 f 更新 +f 或 -f，复杂度是 n sqrt n log n 的，过不去。
对于 f 任意时刻都只有 sqrt n 取值，不妨在更新答案的时候暴力扫描每一种 f 更新，什么数据结构支持整体扫描以及 O(1) 增删呢？-- 维护一个节点是 f，节点值是 ccnt[f] 的**无序双向链表**！
具体来说，由于无序，如果第一次加入直接插到 head 即可，否则增加节点对应值。对于删除，要么值 -1，要么移动 pre 和 nxt 指针删除节点。对于 n 个可能节点再维护一个 in[f] 来判断是否在链表种即可。
对于每次回答询问，从 head 开始不断向 nxt 跳直到 -1，暴力扫描更新答案即可。代码如下：
```CPP
// 不同正频率 f 最多有 sqrt n 种；维护一个 f->ccnt[f] 的无序双向链表，最多 sqrt n 个节点；这样增删 O(1)，查询 O(sqrt n)，总体 n sqrt n + q sqrt n
vector<int> pre(n + 1, -1), nxt(n + 1, -1), ccnt(n + 1, 0);
vector<char> in(n + 1, 0);
int head = -1;
auto inc_f = [&](int f) -> void {
    if (in[f]) {
        ++ccnt[f];
        return;
    }
    in[f] = 1, ccnt[f] = 1;
    nxt[f] = head;
    if (head != -1) pre[head] = f;
    head = f;
};
auto dec_f = [&](int f) -> void {
    if (!in[f]) return;
    if (ccnt[f] > 1) {
        --ccnt[f];
        return;
    }
    ccnt[f] = 0, in[f] = 0;
    if (f == head) head = nxt[f];
    if (pre[f] != -1) nxt[pre[f]] = nxt[f];
    if (nxt[f] != -1) pre[nxt[f]] = pre[f];
    pre[f] = -1, nxt[f] = -1;
};
auto query_mx = [&]() -> int {
    int mx = 0;
    for (int f = head; f != -1; f = nxt[f]) {
        mx = max(mx, f * ccnt[f]);
    }
    return mx;
};

vector<int> ans(q);                     // 询问对应的答案
vector<int> cnt(MX);
auto add = [&](int i) -> void {         // 下标为 i 的元素进入查询区间
    int x = a[i];
    dec_f(cnt[x]);
    ++cnt[x];
    inc_f(cnt[x]);
};
auto del = [&](int i) -> void {         // 下标为 i 的元素离开查询区间
    int x = a[i];
    dec_f(cnt[x]);
    --cnt[x];
    if (cnt[x]) inc_f(cnt[x]);
};
// 处理查询
int L = 0, R = -1;
for (auto& [l, r, id] : qs) {
    while (L > l) add(--L);
    while (R < r) add(++R);
    while (L < l) del(L++);
    while (R > r) del(R--);
    ans[id] = query_mx();
}
```
