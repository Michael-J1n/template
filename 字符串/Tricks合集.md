## 基础算法/思想相关

1. 【LC2565】给定字符串 s,t，可以从 t 中删去任意位置的字符，使得 t 为 s 的一个子序列。记最左侧的删除字符的下标为 l，最右侧为 r，那么代价为 r-l+1。求最小代价是多少。
关键观察：由于得分为 r-l+1，因此把 [l+1,r-1] 里的字符也全都删掉后，得分不改变，但剩下的 t 更容易成为 s 的子序列了。因此全部删掉是更优的。
因此，可以把问题转化为：选择 t 的一个最短子串删除，使得剩下的 t 是 s 的子序列。
考虑剩下的 t 被分为两块（前面一段以及后面一段），分别匹配到 s 的前缀部分和 s 的后缀部分。因此可以进行前后缀分解：
定义 pre[i]=s[0..i] 可以匹配的 t 的前缀的最大长度，suf[i]=s[i..n-1] 可以匹配的 t 的后缀的最大长度，使用子序列判断匹配的算法进行计算即可。
枚举分割点，pre[i]+suf[i+1] 即为当前可以保存的最长长度，用 t 的长度减去即为最短的需要删除的子串长度。
```CPP
vi pre(n), suf(n);  // pre[i]=s[0..i]匹配的最长t前缀，suf[i]=s[i..n-1]匹配的最长t后缀
int j = 0, cur = 0;
for (int i = 0; i < n; ++i) {
    if (j < m && s[i] == t[j]) ++cur, ++j;
    pre[i] = cur;
}
j = m - 1, cur = 0;
for (int i = n - 1; ~i; --i) {
    if (~j && s[i] == t[j]) ++cur, --j;
    suf[i] = cur;
}
```
这个**前后缀分解**也是一个很重要的处理手段（在考虑删除子串问题时）。
类似的题目还有 CF1203D，给定串 s 和其一子序列 t，求删除 s 的最长子串使得 t 仍然是子序列。
这次前后缀在 t 上分解：定义 pre[i] 为 t[0..i] 可从左到右贪心匹配到 s 的右侧下标，suf[i] 为 t[i..m-1] 可从右到左贪心匹配到的 s 的左侧下标；
枚举 t 的分割线，记 l=pre[i],r=suf[i+1]，那么由于贪心，l尽可能左并且r尽可能右，因此中间的 r-l+1 是可以删除的尽可能大的段。
实现中注意分割线的枚举是要从 -1 开始的。i=-1 时只有右边部分，l设置为0，i=m-1 时只有左边部分，r设置为n-1.
```CPP
void solve() {
	string s,t;cin>>s>>t;
	int n=s.size(),m=t.size();
	int j=0;
	vi pre(m,n),suf(m,-1);
	for(int i=0;i<m;++i){
		while(j<n&&s[j]!=t[i])++j;
		if(j==n)break;
		pre[i]=j,++j;
	}
	j=n-1;
	for(int i=m-1;~i;--i){
		while(~j&&s[j]!=t[i])--j;
		if(j==-1)break;
		suf[i]=j,--j;
	}
	int res=0;
	for(int i=-1;i<m;++i){
		int l=i>=0?pre[i]+1:0,r=i+1<m?suf[i+1]-1:n-1;
		res=max(res,r-l+1);
	}
	cout<<res<<endl;
}
```

2. 在类似**子序列匹配**的问题中，考虑next自动机也是个好的选择。例如【1924A】，给定一个字符串，求构造一个固定长度的字符串使得不是子序列：
考虑子序列匹配的算法，依次匹配，由于需要不是子序列，每次只需要取 next[p][j] 最大的 j；如果这个 next[p][j] 到了末尾说明匹配不上，那么这就是合法子序列
否则虽然可以继续匹配，但是贪心的来看由于所有下一项都能得到匹配，选择最远的那个可以跳过最多的匹配（剩余字符匹配上的池子更小了，更容易匹配不到）。更新 p=next[p][j]+1 即可。


## 回文相关

1. 给定一个字符串 s 和整数 k，求最多能选出多少个互不重叠的长度至少为 k 的回文子串。
首先发现这是一个划分dp的形式：去掉最后一个选择的是自问题，因此为dp，并且互不重叠暗示了划分。
可以定义朴素 DP，dp[i]=考虑 s[0..i]，选出互不重叠的长度为 k 的子串的最多个数。转移时暴力枚举 j，如果 s[j..i] 是满足要求的回文，那么 f[i] <-max- 1+f[j-1]。这样是 O(nk) 的。
优化：考虑任意一个合法方案，其若含有一个长度 >=k+2 的回文子串被选择，那么删掉首尾不计入，一定也是一个合法情况，且个数不会变的更少
因此，一定存在一个最优方案，使得其中所有回文子串的长度要么是 k，要么是 k+1（否则可以不断删去首尾不改变计数且让长度变为k或k+1）。那么在 i 处转移时，只需要考虑 j=i-k+1 与 i-k 即可。这样即优化为 O(n)。
实现上，用马拉车来判断区间是否回文（比字符串哈希的常数小很多）

2. 【CF17E】给定字符串 s，求 s 有多少对回文串相交
直接计算相交对比较复杂，考虑转化成：相交对总数 = 总对数 - 不相交对数
假设一共有 x 个回文串，那么总对数为 C(x,2)；考虑如何求不相交对数。记此数量为 cnt
从小到大遍历 i，将 cnt 加上 { i 结尾的回文串个数 * 总和{j 开头的回文串个数, j > i} }，累加结束即为 cnt 值。
这里不用加左边与 i 结尾回文串不相交的回文串个数，由于统计左边串时就计算了所有与右边不相交串的贡献。
实现上，i 结尾与开头的回文串个数在马拉车模板中已经实现（本质差分思想），遍历计算时只需要一个 st[i] 的前缀和预处理出即可。
